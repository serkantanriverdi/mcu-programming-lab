# Security and private data

Do not put access tokens, passwords, private keys or raw device backups in
issues, pull requests, screenshots or committed files. Programming checkpoints
under `records/` can contain private firmware and EEPROM data.

If a credential is exposed, revoke it at its provider. Deleting a line from
the latest commit does not remove it from existing clones or old history.

For a sensitive vulnerability, use GitHub private vulnerability reporting
when available, or contact the maintainer privately through their GitHub
profile. Do not publish a working credential as evidence.
